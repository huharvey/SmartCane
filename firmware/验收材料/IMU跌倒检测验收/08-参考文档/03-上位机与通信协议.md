# 上位机与 SC1 通信协议

## 1. 链路划分

| 链路 | 端点 | 用途 |
|---|---|---|
| CH340 UART0 | 115200, 8N1 | 5 Hz 传感器/状态遥测与双向控制 |
| HTTP 80 | `/capture`、`/api/status` | 抓拍、调试和浏览器兼容接口 |
| MJPEG 81 | `/stream` | 上位机实时图传 |
| 在线地图 | 按当前视口加载 OSM 瓦片 | GPS 底图；有缓存且不做预下载 |

传感器数据固定走串口，图像固定走 Wi-Fi。两条链路断开时互不影响，上位机分别显示状态。

## 2. 串口帧

每帧以换行结束，协议帧固定以 `SC1 ` 开头。设备的人工启动日志不带此前缀，上位机会忽略或放入日志区。

```text
SC1 HELLO {"protocol":"smartcane.serial","version":1,"baud":115200}
SC1 TEL {"protocol":"smartcane.telemetry","version":1,...}
SC1 ACK PING
SC1 ERR unknown_command
```

跌倒标定时可临时开启“每个新 JY901S 样本一行”的紧凑 CSV 数据流：

```text
SC1 CMD IMU STREAM ON
SC1 IMU HEADER seq,t_ms,ax_g,...,fall_latched
SC1 IMU 1,12345,0.0100,...,NORMAL,0,0
SC1 CMD IMU STREAM OFF
```

`seq` 在设备端按新样本递增，上位机利用序号间隙计算串口/队列丢帧；`t_ms`
是该组姿态帧到达 ESP32 的时间。CSV 同时给出原始九轴、`a_g`、`g_dps`、
`tilt_deg`、跌倒候选阶段和阈值布尔量。数据流关闭时不产生额外高频输出。

遥测 JSON 字段：

- 系统：`uptime_ms`、`alarm`、`buzzer`、`light`、`sos_latched`、`fall_latched`；
- 测距/光照：`distance_cm`、`lux`，无效值为 JSON `null`；
- IMU：`valid`、三轴 `ax/ay/az_g`、三轴 `gyro_*_dps`、`roll/pitch/yaw_deg`、`accel_g`；
- GPS：`gps` 为当前定位的 `valid`、`lat`、`lon`、`speed_kmh`、`altitude_m`、`satellites`、`utc`；`last_fix` 为本次上电以来最后一次有效定位，含 `available`、经纬度、卫星数、UTC 和 `age_ms`。当前失星时 `gps.valid=false`，但 `last_fix` 会保留供网页显示最后位置；断电重启后会清空。
- 网络/相机：`ip`、`ap_mode`、`rssi`、`camera`。

## 3. 上位机命令

```text
SC1 CMD PING
SC1 CMD GET
SC1 CMD SOS
SC1 CMD CANCEL
SC1 CMD LIGHT AUTO
SC1 CMD LIGHT ON
SC1 CMD LIGHT OFF
SC1 CMD IMU STREAM ON
SC1 CMD IMU STREAM OFF
```

设备只接受上述白名单命令。`GET` 立即发一帧遥测；其他有效命令先进入已有命令队列，再由主循环处理。

## 4. 地图与坐标

GPS 与导入文件统一按 WGS-84 的 `纬度, 经度` 显示。GeoJSON 内部仍遵循标准的 `[经度, 纬度]` 顺序。上位机使用 Web Mercator 绘制在线瓦片、实时轨迹和导入矢量；GPX、KML 会先转换成内存中的 GeoJSON。

底图只请求用户当前看到的瓦片并尊重 HTTP 缓存。ESP32 独立热点没有互联网时，底图请求会失败，但暗色坐标网格、GPS点及导入/实时轨迹继续工作。

## 5. 上位机职责边界

跌倒检测与状态机仍完全运行在 ESP32 上。Qt 只记录固件给出的原始量、派生量和
判定过程，不在电脑端替代实时报警。后续离线网页可以重放 CSV 并比较候选阈值，
但修改后的阈值必须重新编译烧录，再通过独立实机数据验证。
