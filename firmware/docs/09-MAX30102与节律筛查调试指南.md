# MAX30102 与节律筛查调试指南

## 1. 当前实现与本轮目标

当前固件已经具备 MAX30102 RED/IR FIFO 读取、手指检测、基础滤波、峰值检测、HR、
课堂演示级 SpO₂ 估算、SQI、15 秒 IBI/HRV 特征窗口和 6 特征 INT8 基线分类器。
本轮调试要把“能显示数值”推进到“原始数据可追溯、算法可验证、误差可量化”。

必须明确两个边界：

1. 当前 SpO₂ 公式 `110 - 25R` 是课堂/原型近似，不是成熟医疗算法；
2. 当前节律权重是集成基线，`model_calibrated=false`，没有经过 ECG 标注公开数据训练，不能声称能诊断房颤。

## 2. 本次已经补充的调试能力

### 2.1 固件串口协议

新增命令：

```text
SC1 CMD PPG STREAM ON
SC1 CMD PPG STREAM OFF
```

新增数据帧：

```text
SC1 PPG HEADER seq,t_ms,red,ir,red_dc,ir_dc,red_ac,ir_ac,filtered_ir,envelope,peak_candidate,beat_accepted,ibi_ms,finger,sqi,hr_bpm,spo2_pct,valid,fifo_overflow
SC1 PPG <对应 CSV 数据>
```

IMU 与 PPG 高频流会自动互斥。普通 5 Hz JSON 遥测继续运行，用于补充节律窗口、
IMU 运动量、推理耗时和模型内存字段。

### 2.2 Qt 页面

新增“MAX30102 · PPG/血氧数据采集”区域，支持：

- 试验编号和场景标签；
- 开始、动作/放指标记、停止并保存；
- 25 Hz 实际采样率、序号丢帧、最大间隔、FIFO 溢出；
- 手指覆盖率、有效率、平均 SQI、ADC 削顶率；
- RED/IR AC、滤波 IR、接受峰和 SQI 实时曲线；
- CSV 自动保存及试验索引；

## 3. 先确认硬件事实

### 3.1 I²C 总线

目标描述写的是“第二路 I²C”，但当前实机配置为：

```cpp
MAX30102_USE_PRIMARY_I2C = true
```

也就是 MAX30102 当前仍在主 I²C GPIO41/42 上。可先按现状完成算法调试；如果后续
启用同为 `0x57` 的超声模块，必须将两个器件分到不同总线或使用 I²C 多路复用器，
否则地址冲突。不要在硬件尚未改线时直接把配置改成第二路。

### 3.2 真实采样率

MAX30102 ADC 设置为 100 samples/s，FIFO 配置 `SMP_AVE=4`。官方手册说明硬件会
对相邻样本平均并抽取，因此每个 FIFO RED/IR 对应 4 个 ADC 转换，实际输出为：

```text
100 / 4 = 25 Hz
每个 FIFO 样本间隔约 40 ms
```

固件现在按 25 Hz 重建 FIFO 批量读取的时间戳。调试时以 Qt 显示的真实频率为准。
官方依据：[MAX30102 Data Sheet](https://www.analog.com/media/en/technical-documentation/data-sheets/MAX30102.pdf)。

## 4. 第一步：链路与 FIFO 验收

先选“无手指空载”，记录 15 秒；再选“稳定覆盖·静止”，记录 60 秒。

检查：

| 指标 | 建议通过条件 |
|---|---|
| 实际采样率 | 24～26 Hz |
| 样本间隔中位数 | 约 40 ms |
| 序号丢帧 | 0；长记录允许低于 0.5% |
| 最大间隔 | 通常不超过 120 ms |
| FIFO overflow | 必须为 0 |
| 无手指状态 | `finger=false`，HR/SpO₂ 不输出有效值 |
| 稳定覆盖 | 原始值不长期接近 262143，削顶率应接近 0 |

如果 overflow 增加或频率明显低于 25 Hz，先检查 I²C、SensorTask 阻塞和串口带宽，
不要先调 HR/SpO₂ 公式。

## 5. 第二步：原始 PPG 与滤波验证

依次采集以下场景，每类先做 1 次确认流程，再做 3～5 次：

| 场景 | 单次时长 | 主要用途 |
|---|---:|---|
| 无手指空载 | 15 s | 背景、手指阈值、误触发 |
| 稳定覆盖·静止 | 60 s | 波形、峰值、IBI、HR/SpO₂ |
| 重复放置/移开 | 6 次 | 手指检测响应与状态复位 |
| 轻压 / 正常压 / 重压 | 各 30 s | 接触压力、DC、AC、削顶影响 |
| 手指轻微移动 | 30 s | 局部运动伪影 |
| 拐杖轻微晃动 | 30 s | IMU 运动抑制与节律状态 |
| 强环境光 | 30 s | 环境光鲁棒性 |
| 运动后恢复 | 90 s | 心率变化跟踪能力 |

每次统一流程：

1. 连接 TTL，确认 MAX30102 显示在线；
2. 选择场景，填写唯一编号；
3. 点击“开始记录”，先留 5 秒基线；
4. 点击“动作/放指开始”；
5. 完成场景并保持到规定时长；
6. 点击“停止并保存”；
7. 检查采样率、丢帧、overflow、手指率、有效率、SQI 和削顶率；
8. 异常试验写入备注，不要删除后假装未发生。

曲线应重点观察：

- RED 与 IR AC 是否具有同周期脉搏形态；
- 滤波 IR 是否保留主峰，同时减少基线漂移和高频毛刺；
- 白色峰线是否与肉眼主峰一一对应；
- 移动时是否出现大幅伪影，SQI 是否下降；
- 轻压时信号是否过弱、重压时是否削顶或 AC 反而下降。

## 6. 第三步：手指检测、SQI 和有效率

从 `no_finger` 与 `finger_reposition` CSV 统计：

```text
手指检测灵敏度 = 正确识别有手指的样本 / 实际有手指样本
无手指特异度 = 正确识别无手指的样本 / 实际无手指样本
放指响应时间 = ACTION_START 到 finger=true 的时间
移开响应时间 = 实际移开到 finger=false 的时间
有效率 = valid=true 样本 / 有手指样本
```

当前手指阈值为 IR `50000`。只有无手指与不同压力数据都收齐后才考虑调整；不要只用
一根手指的一次记录定阈值。

## 7. HR/SpO₂ 精度对照：本阶段暂缓

当前没有标准参考仪器，本阶段不设置参考对照组，Qt 也不提供参考 HR/SpO₂ 输入及
MAE 统计。现有数据只用于验证 PPG 波形、有效率、趋势和算法链路，不能据此声称 HR
或 SpO₂ 测量精度已经完成校准。以后具备参考仪器时，再单独恢复同步对照流程。

禁止通过憋气、遮挡呼吸或其他危险方式人为制造低血氧。当前 SpO₂ 公式仍然只是课程
原型基线，不能作为医疗诊断依据。

## 9. 第六步：节律筛查本机验证

本机采集不能可靠产生房颤真实标签，因此主要验证数据链和误报抑制：

1. “节律稳定窗口”静止 60 秒 × 10 次；
2. “手指轻微移动”30 秒 × 5 次；
3. “拐杖轻微晃动”30 秒 × 5 次；
4. 检查前 15 秒状态为 `COLLECTING`；
5. 运动时应进入 `MOTION_ARTIFACT`，不能输出高置信异常；
6. 稳定窗口记录 IBI mean、SDNN、RMSSD、pNN50、beat count、分类、置信度；
7. 统计正常静止误报次数、运动伪影抑制率、有效窗口率和连续运行假告警次数。

本机正常数据的目标是证明“不会乱报”和“特征实现一致”，不是证明能识别房颤。

## 10. 第七步：公开数据训练

选择带 ECG 参考标签的公开 PPG 节律数据，而不是仅有普通运动 PPG 的数据集。处理时：

1. 按受试者划分训练、验证、测试集，禁止同一人的窗口同时进入训练和测试；
2. 将公开 PPG 的峰值/IBI 提取流程与固件保持一致，或明确记录差异；
3. 以 15 秒窗口计算当前 6 个输入：IBI CV、RMSSD/mean IBI、pNN50、最大相邻 IBI 差/mean、SQI、心率越界分数；
4. 先训练可解释的逻辑回归/线性分类器，再考虑小型 MLP；
5. 完成 INT8 量化，导出权重并替换 `RhythmClassifier.cpp` 中的基线常量；
6. 只有独立测试集通过后，才把 `RHYTHM_MODEL_CALIBRATED` 改为 `true`。

必须报告：

- 三分类混淆矩阵；
- 每类 precision、recall/sensitivity、specificity、F1；
- macro-F1、balanced accuracy，条件允许时给 AUROC；
- 受试者数量、窗口数量、无效窗口比例；
- 连续窗口确认前后的召回率与误报率；
- 每小时假告警数。

## 11. 端侧性能记录

固件遥测与 PPG CSV 已补充：

- `rhythm_inference_us`：最近一次 6 特征模型推理耗时；
- `rhythm_inference_count`：累计推理次数；
- `rhythm_model_bytes`：权重和偏置常量字节数；
- `rhythm_classifier_state_bytes`：分类器状态对象字节数。

本次构建结果：

```text
RAM  : 55300 / 327680 bytes（16.9%）
Flash: 1012305 / 1966080 bytes（51.5%）
```

烧录后至少记录 30 次推理的 `inference_us`，报告中给平均值、P95 和最大值。训练后的
模型替换基线模型时，应重新记录同样指标并比较 RAM、Flash 和推理耗时增量。
