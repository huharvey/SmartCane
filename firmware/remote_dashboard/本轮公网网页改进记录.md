# 本轮公网网页改进记录

## 改动边界

本轮只修改 `remote_dashboard`，没有改动实机固件、跌倒检测阈值、MAX30102 算法、TinyML 模型、GPS 驱动、摄像头驱动或已经验证的 MQTT 发布逻辑。

## 已完成

1. 将公网页面整理为 `frontend/index.html`、`frontend/app.css`、`frontend/app.js`，Flask 不再使用 `templates/` 与 `static/` 旧页面。
2. 复用固件内置网页的 900px 卡片布局和深色配色，保留心率、血氧、PPG 质量、节律筛查、GPS、告警、设备健康和事件提示。
3. 新增 `/api/status`，它与 `/api/state` 一样读取 Python 后端保存的 MQTT 最新状态，而不是访问 ESP32。
4. `/api/stream` 继续使用 SSE；无消息时每 15 秒重新计算状态，设备断线后已打开的网页也会自动变成离线。
5. MQTT 后端从通配符订阅改成只订阅 presence、telemetry、vitals、gps、event 五个 Topic。
6. StateStore 增加 Topic 白名单、JSON 对象检查与最后有效 GPS 缓存。GPS 失星或设备离线时显示最后位置。
7. 高德静态地图由服务器端 `/api/map.png` 代理，Key 只放在服务器环境变量中；浏览器只获得地图图片。
8. 公网页面没有 SOS、解除告警、灯光控制接口或按钮。
9. 摄像头区域明确提示“仅支持近场访问”，没有 `location.hostname + ':81/stream'`。
10. 保留浏览器登录保护，增加公网 IP 优先的 Nginx、Docker Compose、systemd 示例和完整部署验收指南；域名与 HTTPS 改为可选安全升级。
11. 增加 `.dockerignore`，防止 `.env` 被打入 Docker 镜像；容器改为非 root 用户运行。
12. 将进程存活 `/livez` 与 MQTT 就绪 `/readyz` 分开，避免 Broker 短时断线导致容器被误判为崩溃。

## 验证结果

- Python 语法检查通过。
- Python 单元测试原有 18 项全部通过，并新增 2 项部署边界测试，检查 Docker 仅绑定本机 8080、Nginx 公网 IP 模板与 SSE 反向代理配置。
